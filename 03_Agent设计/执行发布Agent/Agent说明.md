# 执行发布Agent · 设计文档

> 版本：V1.0 | 状态：设计中 | 2026-07-31

---

## 一、Agent 职责定义

### 1.1 一句话职责

**执行发布Agent = 将内容生成Agent产出的素材包，自动填入抖音创作者中心，停在最终发布确认页。**

### 1.2 核心职责（5条）

| # | 职责 | 说明 |
|---|------|------|
| 1 | **接收素材包** | 从内容生成Agent获取标准化输出（图片路径、标题、正文、标签、BGM） |
| 2 | **浏览器自动化** | 打开Chrome → 导航至抖音创作者中心 → 进入图文发布页 |
| 3 | **内容填入** | 按顺序：上传图片 → 填写标题 → 填写正文 → 添加标签 → 选择BGM |
| 4 | **发布前自检** | 逐项核对填入内容与素材包是否一致，不一致则修正 |
| 5 | **等待人工确认** | 停在最终发布按钮页面，明确提示用户"请检查后点击发布" |

### 1.3 明确不做的事（V1边界）

| 不做 | 原因 |
|------|------|
| ❌ 自动点击"发布"按钮 | 保留人工最终确认（安全原则） |
| ❌ 账号登录/扫码 | 用户手动完成登录，Agent从已登录态开始 |
| ❌ 定时发布/定时发送 | V2功能 |
| ❌ 多平台发布 | 仅抖音创作者中心 |
| ❌ 发布结果回调 | 发布后不追踪（复盘Agent负责） |
| ❌ 网络异常重试超过3次 | 超过3次停止并通知用户 |

### 1.4 与其他Agent的关系

```
内容生成Agent ──(素材包)──► 执行发布Agent ──(发布记录)──► 复盘Agent(未来)
                                │
                                ▼
                         抖音创作者中心
                              │
                              ▼
                         用户手动确认发布
```

### 2.2 各步骤详细说明

#### 步骤1：接收素材包

输入来源：内容生成Agent输出的标准化JSON文件（`publish_package.json`）

#### 步骤2：素材包校验

校验清单：
- [ ] 图片文件是否存在（至少1张，最多35张）
- [ ] 图片格式是否为 jpg/png/webp
- [ ] 标题是否在1-55字之间
- [ ] 正文是否非空
- [ ] 标签数量是否 ≤ 5个
- [ ] 标签每个是否 ≤ 10字

#### 步骤3：连接浏览器

```
启动Chromium（Playwright）
    │
    ├── 使用持久化用户目录（保留登录Cookie）
    │   路径: ~/.claude/douyin_user_data/
    │
    ├── 检查是否已登录
    │   方法: 访问 https://creator.douyin.com/
    │   判断: 页面是否跳转到登录页
    │
    └── 未登录 → 停止流程，弹窗提示用户先登录
```

#### 步骤4：导航至发布页

目标URL：`https://creator.douyin.com/creator-micro/content/upload`

等待策略：
1. 等待页面 `networkidle`（网络空闲）
2. 等待发布表单区域可见
3. 如果30秒仍未加载 → 刷新重试（最多3次）

#### 步骤5：上传图片

使用三级降级策略：

```
第一级：尝试通过 <input type="file"> 直接上传
    │  选择器: input[type="file"][accept*="image"]
    │  方法: input.set_input_files(image_paths)
    │
    ├── 成功 → 等待上传进度条消失 → 进入步骤6
    │
    └── 失败 → 第二级
         │
第二级：通过"上传按钮" + 文件选择对话框
    │  方法: 点击上传区域 → 等待文件对话框 → set_input_files
    │
    └── 失败 → 第三级
         │
第三级：AI截图识别 + 坐标点击
    方法: 截图 → Claude/GPT分析 → 找到"上传"按钮坐标 → 点击
    │
    └── 失败 → 停止，通知用户手动上传
```

#### 步骤6-8：填写标题/正文/标签

每个填写步骤的通用策略：

```
1. 定位输入框（AI Vision识别 + DOM选择器双保险）
2. 清空已有内容（Ctrl+A → Delete）
3. 逐字输入或粘贴（粘贴优先，减少输入延迟）
4. 验证填入内容（读取输入框值，与目标值对比）
5. 不匹配 → 重试1次
```

标签特殊处理：
- 逐个添加标签（输入标签名 → 等待下拉建议 → 回车确认）
- 每个标签添加后等待500ms

#### 步骤9：添加BGM（音乐模块推荐）

```
数据源：优先 bgm_candidates（音乐推荐模块输出，带匹配评分）
        回退 content.bgm（generator 旧版硬编码列表）

三级降级：
  1. 选择器定位音乐入口（选择音乐/添加音乐/配乐）→ 搜索 search_keyword → 选中第一首 → 确认
  2. AI Vision 识别音乐入口 → 搜索 → 选中
  3. 失败 → 输出手动搜索关键词 + 截图存 output_dir，不阻塞发布
```

关键原则：
- BGM 失败**不影响**图片/标题/正文（核心内容），流程照常推进到自检
- 只添加排名第一的推荐（最优匹配），其余作为备选输出在摘要中
- 全程不点击"发布"按钮（BGM 操作在填写阶段完成）

#### 步骤10：发布前自检

```
逐项对比：
┌──────────────────┬─────────────────────────────────┐
│ 检查项            │ 方法                             │
├──────────────────┼─────────────────────────────────┤
│ 图片数量正确      │ 截图 → AI识别已上传图片数量       │
│ 标题内容一致      │ 读取输入框value → 对比目标标题    │
│ 正文内容一致      │ 读取输入框value → 对比目标正文    │
│ 标签全部添加      │ 截图 → AI识别已添加标签           │
│ BGM已选择(可选)   │ 截图 → AI识别音乐是否已挂上       │
└──────────────────┴─────────────────────────────────┘

任一核心项不通过 → 修正 → 重新检查
核心项全部通过 → 进入步骤11
（BGM未挂上仅记录warning，不阻断）
```

#### 步骤11：截图保存

- 截取整个发布确认页面
- 保存路径：`output/第N周/发布预览_{时间戳}.png`
- 同时复制到剪贴板

#### 步骤12：通知用户

显示摘要：

```
━━━━━━━━━━━━━━━━━━━━━━━━━
  发布内容已填入完毕 ✓

  标题：{标题}
  图片：{N}张
  标签：{标签列表}
  BGM：{已添加/待手动}

  📍 浏览器已停在发布确认页
  ⚠️ 请自行检查后点击"发布"
━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 2.3 异常处理流程

```
任何步骤出错
    │
    ├── 可恢复错误（DOM变化、加载超时）
    │   ├── 第1次：重试当前步骤
    │   ├── 第2次：刷新页面后重试
    │   └── 第3次：重启浏览器后重试
    │
    ├── 不可恢复错误（被限流、账号异常）
    │   └── 截图当前页面 → 保存错误日志 → 通知用户
    │
    └── 重试3次仍失败
        └── 保存当前进度 → 生成手动发布指南 → 通知用户
```

| `VALIDATION_FAILED` | 素材校验失败 | 素材包格式不正确，请检查{字段} |

| `RATE_LIMITED` | 被限流 | 操作过于频繁，请等待5分钟后重试 |

## 四、与内容生成Agent的连接方式

### 4.1 连接架构

```
┌─────────────────────┐         ┌─────────────────────┐
│   内容生成Agent      │         │   执行发布Agent      │
│                     │  写入    │                     │
│  1. 接收用户输入     │────────►│  1. 轮询监听output/  │
│  2. 生成图文内容     │publish_ │  2. 读取素材包       │
│  3. 生成标题正文     │package  │  3. 执行发布流程      │
│  4. 选择BGM         │  .json  │  4. 写入发布报告      │
│  5. 输出素材包       │         │                     │
└─────────────────────┘         └─────────────────────┘
          │                              │
          │       ┌───────────┐          │
          └──────►│ output/   │◄─────────┘
                  │  第N周/   │
                  │           │
                  │ • publish_package.json
                  │ • 封面图.png
                  │ • 打标签代码图.png
                  │ • 生活照.png
                  │ • 发布预览_xxx.png
                  │ • publish_report_xxx.json
                  └───────────┘
```

### 4.2 连接方式：文件系统桥接

**选择理由：**
- 两个Agent独立运行，不需要同时在线
- 文件系统是最稳定的中间层
- 发布包可被人工查看、修改（用户在发布前可以编辑JSON调整文案）
- 天然支持版本追溯

**具体机制：**

```
触发方式（V1采用方式A）：

方式A：用户手动触发（V1默认）
  用户在GUI中点击"开始发布" → 执行发布Agent读取最新的publish_package.json

方式B：文件监听触发（V1.5可选）
  Watchdog监听output目录 → 检测到新的publish_package.json → 自动启动

方式C：主控Agent调度（V2.0）
  主控Agent在内容生成完成后 → 自动调度执行发布Agent
```

### 4.3 素材包存储规范

```
output/
└── 第{N}周_YYYYMMDD/
    ├── publish_package.json        ← 标准素材包（发布Agent输入）
    ├── 封面图.png                   ← 统一模板生成
    ├── 打标签代码图.png             ← 代码+标签叠加
    ├── 生活照.png                   ← 原始生活照
    ├── 文案.md                      ← 人类可读的文案备份
    ├── 发布预览_{timestamp}.png     ← 发布Agent截图
    └── publish_report_{timestamp}.json ← 发布Agent报告
```

### 4.4 人工介入点

用户在发布前可以：
1. 直接编辑 `publish_package.json` 修改标题/正文/标签
2. 替换 `output/第N周/` 中的图片文件
3. 在发布Agent自检通过后、最终发布前，在浏览器中二次确认

## 五、技术方案选择

### 5.1 技术栈

| 层 | 技术 | 版本 | 选择理由 |
|----|------|------|---------|
| 浏览器自动化 | **Playwright** | ≥1.45 | ✅ 项目架构已选定；支持Chromium持久化用户目录（保留登录态）；比Selenium更快更稳定 |
| 编程语言 | **Python 3** | ≥3.10 | ✅ 与内容生成Agent统一；Playwright Python绑定成熟 |
| AI视觉识别 | **Claude/GPT Vision** | - | 截图后发送至多模态模型识别UI元素位置 |
| 文件监听 | **Watchdog** | ≥4.0 | V1.5可选，监听output目录新文件 |
| 配置管理 | **JSON** | - | 轻量，无需引入数据库 |
| 浏览器 | **Chromium** | 内置 | Playwright自带，无需用户安装 |

### 5.2 核心技术决策

#### 决策1：Playwright持久化上下文 vs 每次新建

```
选择：持久化上下文（persistent context）

路径：~/.claude/douyin_user_data/

好处：
- 用户只需登录一次，Cookie/Token自动保存
- 后续发布无需重复扫码
- 接近真实用户操作，降低风控概率

风险：
- Cookie过期需重新登录（Agent检测到未登录时提示用户）
```

#### 决策2：粘贴 vs 逐字输入

```
选择：粘贴优先（Ctrl+V）

理由：
- 逐字输入速度慢，且中间可能触发平台的实时检测
- 粘贴是一次性操作，速度快，成功率更高
- 如果粘贴失败（部分平台阻止粘贴），回退到逐字输入
```

#### 决策3：AI Vision识别策略

```
选择：V1.0以DOM选择器为主，AI Vision为辅助兜底

理由：
- 抖音创作者中心的DOM结构相对稳定
- DOM选择器速度快、成本低（无API调用）
- AI Vision仅在DOM选择器失败时使用（减少token消耗）
- 遵循项目"Token最小化"设计原则

DOM选择器方案：
- 维护一个选择器映射表（selector_map.json）
- 每个目标元素保存多个候选选择器
- 按优先级尝试，全部失败则启用AI Vision

AI Vision方案：
- 截取当前页面 → 发送至多模态模型
- Prompt："找到{元素描述}的位置，返回中心点坐标"
- 按坐标点击
```

### 6.3 技术风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| 抖音创作者中心DOM结构更新 | 高 | 选择器失效 | 维护selector_map.json + AI Vision兜底 |
| 平台反自动化检测 | 中 | 账号限流 | 持久化用户目录模拟真人 + 操作间隔随机化 |
| 图片上传控件变化 | 中 | 上传失败 | 三级降级策略 + 最终手动兜底 |

## 七、附录

### A. 抖音图文发布页DOM参考（需实际验证）

> 以下为设计阶段推断，开发时需实际访问抖音创作者中心确认。

| 元素 | 推断特征 | 备注 |
|------|---------|------|
| 上传区域 | 通常为拖拽区域或`<input type="file">` | 图文和视频上传路径可能不同 |
| 标题输入框 | `placeholder` 通常包含"标题" | 限制55字 |
| 正文编辑区 | 通常为`contenteditable`或富文本编辑器 | 支持换行 |
| 标签输入 | 独立的标签输入框，输入后出现下拉建议 | 回车确认 |
| 音乐入口 | 按钮文字"选择音乐"/"添加音乐"/"配乐" | 点击后弹出搜索面板；DOM待实测标注 |
| 音乐搜索框 | 面板内 `input[placeholder*="搜索"]` | 输入后回车，展示歌曲列表 |
| 发布按钮 | 按钮文字为"发布" | V1不点击 |

### B. 操作间隔建议

为避免被平台识别为自动化操作：

| 操作 | 间隔 |
|------|------|
| 页面打开后等待 | 2-3秒 |
| 图片上传后等待 | 3-5秒（等待预览生成） |
| 各填写步骤之间 | 500ms-1s（模拟真人） |
| 标签添加间隔 | 500ms |
