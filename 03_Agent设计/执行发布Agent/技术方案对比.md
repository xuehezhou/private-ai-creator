# 执行发布Agent · 技术方案对比

> 2026-07-31 | 决策文档

---

## 三种方案概述

| | 方案A | 方案B | 方案C |
|---|---|---|---|
| **名称** | Python + Playwright 脚本 | Claude Agent + Browser MCP | 混合方案（Playwright底座 + AI视觉） |
| **核心思路** | 纯代码自动化 | AI驱动浏览器操作 | 代码做基础设施，AI做复杂决策 |
| **运行时** | Python脚本独立运行 | Claude Code对话中执行 | Python脚本 + 按需调用AI视觉 |

---

## 方案A：Python + Playwright 脚本

### 架构

```
publish_agent.py
    │
    ├── validator.py        ← 素材包校验（纯逻辑）
    ├── browser_controller.py ← Playwright启动/导航/截图
    ├── uploader.py         ← 图片上传（三级降级）
    ├── filler.py           ← 标题/正文/标签填充
    ├── self_checker.py     ← 发布前自检
    ├── selector_map.json   ← DOM选择器映射表
    └── reporter.py         ← 报告生成
```

### 分析

| 维度 | 评价 | 说明 |
|------|------|------|
| **开发难度** | ⭐⭐⭐ 中等 | 需要掌握Playwright API、DOM选择器、异步编程。约1500-2000行Python代码。 |
| **稳定性** | ⭐⭐⭐⭐⭐ 高 | 行为完全确定。同一输入→同一输出。不受AI幻觉影响。可精确控制每一步的超时、重试、等待条件。 |
| **维护成本** | ⭐⭐ 偏高 | 抖音前端一改版，selector_map.json就得跟着更新。页面结构变化时，可能需要改多个函数。没有AI理解页面语义的能力。 |
| **适合个人开发者** | ⭐⭐⭐⭐ 适合 | 一次开发，长期零成本运行。不需要API调用。断网也能跑（只要浏览器能打开）。出问题容易调试——日志精确到行号。 |

### 关键风险

```
抖音改版 → 选择器失效 → 必须手动更新 selector_map.json
                                    │
                                    ▼
                          全部DOM选择器失效
                                    │
                                    ▼
                          回退到坐标兜底（成功率仅50%）
```

## 方案B：Claude Agent + Browser MCP

### 架构

```
Claude Agent（对话中运行）
    │
    ├── preview_start        ← 启动Chrome
    ├── preview_navigate     ← 导航到发布页
    ├── preview_snapshot     ← 获取页面结构（accessibility tree）
    ├── preview_click        ← 按语义描述点击元素
    ├── preview_fill         ← 填充输入框
    ├── preview_eval         ← 执行JS读取/写入
    ├── preview_screenshot   ← 截图验证
    └── preview_inspect      ← 检查CSS属性
```

不写脚本。Claude直接操作浏览器，每一步都是"理解页面 → 决定操作 → 执行 → 验证"的循环。

### 实际运行方式

```
用户在 Claude Code 中说：
"把 output/第30周/publish_package.json 发布到抖音"

Claude Agent 执行流程：
  1. 读取素材包JSON
  2. 启动浏览器 → 导航到创作者中心
  3. 看页面截图 → 找到上传区域 → 上传图片
  4. 看页面截图 → 找到标题框 → 填入标题
  5. 看页面截图 → 找到正文框 → 填入正文
  6. 看页面截图 → 找到标签区域 → 逐个添加标签
  7. 截图全页 → 对比素材包内容 → 确认无误
  8. 停在发布页，告知用户核查
```

### 分析

| 维度 | 评价 | 说明 |
|------|------|------|
| **开发难度** | ⭐ 极低 | **几乎零代码。** 写一份Agent Prompt + 一份Skill定义即可。不需要学Playwright API，不需要写选择器映射表。Agent自己会看页面、找元素。 |
| **稳定性** | ⭐⭐⭐ 中等 | 依赖AI理解页面。大多数时候正确，但有时会点错、找错输入框、或对页面结构产生幻觉。同一输入不一定同一结果。 |
| **维护成本** | ⭐⭐⭐⭐⭐ 极低 | 抖音改版？Agent自己看新页面就行，不需要手动更新任何映射表。视觉理解天然适应UI变化。维护成本几乎为零。 |
| **适合个人开发者** | ⭐⭐⭐⭐⭐ 非常适合 | Prompt即代码。你有想法 → 告诉Agent → 它执行。不需要额外学Playwright API。出问题改Prompt就行。 |

### 关键风险

```
AI 对页面元素误判 → 填错输入框 → 内容错位
                                    │
                                    ▼
                        AI 幻觉 → 声称"已成功"但实际未完成
                                    │
                                    ▼
                        每步都消耗Token（~5000 token/次发布）
```

### Token消耗估算

```
操作                    Token消耗（估算）
─────────────────────────────────────
素材包读取+校验           ~500 token
导航+检查登录态           ~2000 token（含截图识别）
上传图片（3张）           ~3000 token（含截图确认）
填写标题                 ~1500 token
填写正文                 ~1500 token
添加标签（3个）           ~3000 token
发布前自检               ~2000 token
─────────────────────────────────────
合计                     ~13,500 token/次
                        ≈ ¥0.07-0.14/次（DeepSeek）
                        ≈ ¥0.54-1.08/次（Claude）
```

## 方案C：混合方案（Playwright底座 + AI视觉兜底）

### 架构

```
publish_agent.py（Python主控）
    │
    ├── Playwright 层（确定性操作）
    │   ├── 浏览器启动/关闭
    │   ├── Cookie持久化
    │   ├── 导航/等待网络空闲
    │   ├── 截图
    │   └── 基础的DOM选择器操作
    │
    └── AI Vision 层（按需调用）
        ├── 元素定位（DOM选择器全部失败时）
        ├── 页面状态判断（"上传成功了吗？"）
        ├── 弹窗识别与处理
        ├── 发布前自检（对比截图与素材包）
        └── 异常诊断（"为什么点击无效？"）
```

### 运行机制

```
每个步骤的执行逻辑：

1. 优先走 Playwright DOM 选择器（零token）
     │
     ├── 成功 → 继续下一步
     │
     └── 失败 → 调用 AI Vision
                  │
                  ├── 截图 → 发给Claude/GPT → 返回操作指令
                  │
                  ├── 成功 → 继续下一步（记录本次AI调用）
                  │
                  └── 失败 → 降级下一级
```

### AI Vision的实际调用场景

```
场景                         触发条件                   调用频率
──────────────────────────────────────────────────────────────
上传按钮定位                  input[type=file]找不到     偶尔
上传完成确认                  无法通过DOM判断进度         每次上传
弹窗识别与关闭                出现非预期遮挡              偶尔
标签下拉建议匹配              抖音标签API变化             可能
发布页自检                    DOM无法读取输入框内容       每次发布
异常诊断                      未知错误                   极少
──────────────────────────────────────────────────────────────
每轮发布AI调用次数：3-8次（主要是上传确认和发布自检）
```

### 分析

| 维度 | 评价 | 说明 |
|------|------|------|
| **开发难度** | ⭐⭐⭐⭐ 较高 | 需要同时掌握Playwright **和** AI Prompt设计。两层逻辑要配合好。代码量最大（~2000行Python + 设计Prompt）。 |
| **稳定性** | ⭐⭐⭐⭐⭐ 极高 | 双层保障。DOM选择器（确定性）+ AI Vision（适应性）= 最强的抗抖动能力。抖音改版？DOM失效时AI自动顶上。AI误判？DOM层的精确验证兜底。 |
| **维护成本** | ⭐⭐⭐ 中低 | 选择器失效不用急着修——AI可以自动顶上。等积累几次AI调用记录后，再批量更新selector_map.json。维护节奏从容。 |
| **适合个人开发者** | ⭐⭐⭐ 一般 | 能力最强，但初期投入最大。适合愿意花一次性时间、之后长期享受稳定性的开发者。 |

### 关键风险

```
初期开发量大 → 两种技术都要学 → 开发周期长
                                    │
                                    ▼
                Playwright和AI Vision之间的切换逻辑可能出Bug
```

## 推荐方案

### 🏆 推荐：方案B → 方案C 渐进路线

**即：先用方案B（Agent+MCP）快速跑通，然后逐步提取确定性操作为方案C中的Playwright底座。**

### 理由

**1. 你是个人创作者，不是软件公司**

方案A是传统软件工程的思路——写完整的自动化测试套件。但你的目标是**发布内容**，不是维护代码。方案B让你用最少代码最快的速度把东西跑起来。

**2. 抖音前端会变，AI不会过时**

无论抖音怎么改版，AI都能看页面、找按钮、填内容。方案A每改一次就要修一次选择器，对于一个人来说这是持续的负担。

**3. 你的项目已经在用Claude Code**

你当前就在Claude Code环境中工作。Browser MCP工具（`preview_*`）已经可用。这意味着方案B几乎零环境搭建成本。

**4. 渐进式升级路径清晰**

```
第1周: 方案B — 纯Agent驱动，跑通全流程
         │
         ▼ 运行10-20次后，发现哪些步骤是重复的
         │
第2周: 提取高频操作为Playwright脚本
         │  例: 浏览器启动、导航、登录态检查 → 确定性脚本
         │  保留: 元素定位、自检 → AI Vision
         │
         ▼ 持续优化
         │
第3周+: 方案C — 脚本底座 + AI智能层
```

### 不推荐方案A直接上的原因

- 你现在不知道抖音发布页的真实DOM结构
- 开发时写的选择器，很可能第一次实际使用就失效
- 一个人维护选择器映射表 → 迟早变成技术债务
- 开发周期长（9天），收益不确定

### 方案B的实施方式

**不是写Python脚本，而是创建一个Claude Code Skill。**

Skill文件内容（`发布到抖音.md`）：

```markdown
# 发布到抖音

当用户说"发布"或"发布到抖音"时执行。

## 输入
读取 {本周output目录}/publish_package.json

## 执行流程

1. 校验素材包完整性
2. 使用 preview_start 启动浏览器
3. 导航至 https://creator.douyin.com/creator-micro/content/upload
4. 检查登录态（未登录则提示用户扫码）
5. 上传图片：找到上传区域 → 填入图片路径
6. 填写标题：定位标题输入框 → 粘贴标题内容
7. 填写正文：定位正文编辑器 → 粘贴正文内容
8. 添加标签：逐个输入标签 → 回车确认
9. 截图全页 → 逐项对比素材包内容
10. 确认无误后 → 告知用户"请检查并点击发布"
11. 绝对不点击"发布"按钮

## 异常处理
- 元素找不到 → 截图 → AI分析页面 → 重试
- 弹窗干扰 → 识别弹窗 → 关闭 → 继续
- 登录过期 → 暂停 → 提示用户登录
```

这就是方案B的全部"代码"。一旦跑通，把最稳定的部分提取出来写成Python脚本（进入方案C）。
