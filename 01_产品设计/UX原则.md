# UX 设计原则

> 适用于私人AI创作助手的所有交互设计 | 2026-07-31

---

## 核心设计原则

### 1. 简单至上

**目标：第一次使用的人也能在3分钟内完成一次发布。**

- 主界面只展示必要信息：周数、主题、学习内容、照片
- 复杂配置隐藏到设置页（API Key、BGM偏好等）
- 一键操作：「生成文案与方案」→「审核通过·发布」

### 2. 明确反馈

**每一步操作都有响应，绝不让用户猜测。**

| 场景 | 反馈方式 |
|------|---------|
| 生成文案中 | 按钮变灰 + 进度提示 |
| 生成完成 | 弹出结果，四个标签页展示 |
| 发布填充中 | 浏览器自动打开，用户可见每一步操作 |
| 发布完成 | 摘要通知 + 截图保存 |
| 错误发生 | 明确错误原因 + 解决建议 |

### 3. 人机协作

**AI 做辅助，人做决策。**

- ✅ AI 生成3个标题 → 用户选1个或自己写
- ✅ AI 填好发布内容 → 用户在浏览器中最终确认
- ✅ AI 推荐BGM → 用户决定用哪个
- ❌ AI 自动发布（绝不会——必须人工点发布按钮）

### 4. 渐进式交互

**先展示核心结果，需要时再展开细节。**

```
主界面：周数 + 主题 + 照片上传（3个核心输入）
    │
    ▼ 点「生成」
    │
结果页：📝 文案 | 🖼️ 图片 | 🎵 音乐 | 🏷️ 标记（4个标签页）
    │
    ▼ 点「发布」
    │
浏览器自动填充 → 最终人工确认
```

### 5. 容错设计

| 场景 | 容错方式 |
|------|---------|
| 忘记保存 | 关闭时自动保存草稿，重开全恢复 |
| API调用失败 | 自动回退离线模板引擎 |
| 图片上传失败 | 三级降级策略，全失败时引导手动 |
| 网络中断 | 保存进度，提示用户检查网络 |
| 误关闭浏览器 | 发布Agent可重新打开继续 |

### 6. 一致性

- 统一术语：全项目使用「周数」「主题」「代码标签」「素材包」
- 统一交互：所有文件选择使用相同的上传按钮样式
- 统一视觉：封面固定模板，每期风格一致

---

## AI 应用特殊原则

### 透明性

- 用户知道哪些内容由AI生成（标注"AI生成"）
- 用户知道AI使用了哪些信息
- 用户知道哪些结果需要人工确认

### 可控性

- 用户可以修改AI生成的任何内容
- 用户可以重新生成
- 用户可以选择不同的方案

### 信任感

- 稳定输出（同一输入 → 同一格式输出）
- 诚实表达能力边界（"我不确定"比瞎编好）
- 发布前人工审核（安全底线）
